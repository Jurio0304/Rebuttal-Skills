# Rebuttal

Start with the deliverable the author wants today. Match the language of the conversation for analysis and the requested language for the reply. With a paper and reviews, first identify the claims that matter to the decision. With a result, a draft or a new comment, enter at that stage and bring in only the earlier context needed for accuracy.

## Choose a stage

| Request | Use | Return |
|---|---|---|
| Understand reviews or find decisive issues | [1 · Intake](references/stages/01-intake.md) | Original question order, evidence already present, and highest-impact gaps |
| Decide what to do before the deadline | [2 · Plan](references/stages/02-plan.md) | Prioritized actions, a feasible comparison or proof, owners and response outlines |
| Interpret completed work or mixed results | [3 · Results](references/stages/03-results.md) | Supported claims and protocol, open issues, changes to the response plan |
| Draft or revise an author reply | [4 · Response](references/stages/04-response.md) and [Writing](references/writing.md) | Paste-ready, reviewer-specific text with a separate evidence/length note when useful |
| Have the reviewers assess a draft | [5 · Simulate and revise](references/stages/05-simulation.md) | One independent agent per reviewer, simulated replies, rating intentions and specific rework |
| A reviewer or AC has written back | [6 · Discussion](references/stages/06-discussion.md) | Answer the new point or draft a procedural message for the intended readers |
| Produce the global response | [7 · Global response](references/stages/07-global.md) | Shared decision issues, evidence, actual reviewer feedback and remaining differences |
| Update the manuscript or check promises | [8 · Revision](references/stages/08-revision.md) | Revision map, or edits to the author-designated version when requested |

For a full cycle follow the table. Pause where new results, real discussion, or author decisions are needed. In a planning-only request, deliver the plan. If the author already supplied enough facts to answer one question, answer it directly. Revision can overlap drafting and discussion when the venue permits.

## Ground the answer

Use the submitted paper, appendix, original reviews and real discussion as the primary record. Track each reviewer's original question number. A shared experiment can serve several reviewers who care about different conclusions. State the comparison, measured outcome and supported claim before adding a relevant boundary. Correct errors directly and keep each qualification close to the finding it affects.

Read the applicable rule card when formatting a reply or revising a paper: [ICML 2026](references/venues/icml-2026.md), [NeurIPS 2026](references/venues/neurips-2026.md), [ICLR 2027](references/venues/iclr-2027.md), [AAAI-27](references/venues/aaai-27.md). For another year or track, use that year's official instructions or the author's invitation. If a field is unknown, flag that field in delivery notes and complete the scientific response using confirmed constraints.

For multi-round work, keep a compact [case record](assets/case-record.md) in the author's working area, or inline when that suffices. Keep facts, evidence location and manuscript version together. A planned run cannot supply a result. Track author response, reviewer acknowledgement, intended rating, recorded rating and actual revision separately. Drafts, predictions and simulated reviewer text stay internal. Only genuine forum events belong in external-facing accounts of discussion.

When a field has a character cap, run the optional [counter](scripts/count_response.py) on the exact text intended for that field. Respect confirmed title/body rules and the platform's displayed count. Deliver clean reply text separately from internal notes, placeholders or simulated feedback. Posting and manuscript upload are author actions unless the user expressly requests them.
